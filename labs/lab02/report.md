### Контрольные вопросы

**1. Что такое системы контроля версий (VCS) и для решения каких задач они предназначаются?**

**Ответ:** Это программные инструменты для отслеживания изменений в файлах и координации работы нескольких человек над одним проектом. Они позволяют сохранять историю, возвращаться к предыдущим версиям, объединять изменения и разрешать конфликты.

**2. Объясните следующие понятия VCS и их отношения: хранилище, commit, история, рабочая копия.**

**Ответ:**
- **Хранилище (репозиторий)** — база данных с историей всех изменений.
- **Commit** — операция фиксации изменений, создающая новую версию файлов.
- **История** — последовательность коммитов, позволяющая просмотреть эволюцию проекта.
- **Рабочая копия** — текущая версия файлов в локальном каталоге, с которой работает пользователь.

**3. Что представляют собой и чем отличаются централизованные и децентрализованные VCS? Приведите примеры VCS каждого вида.**

**Ответ:**
- **Централизованные (CVS, Subversion):** есть единый сервер, где хранится основной репозиторий.
- **Децентрализованные (Git, Mercurial):** у каждого разработчика есть полная локальная копия репозитория.

**4. Опишите действия с VCS при единоличной работе с хранилищем.**

**Ответ:** В локальном репозитории: `git init` (создать) → `git add` (добавить файлы) → `git commit` (зафиксировать изменения) → `git log` (посмотреть историю).

**5. Опишите порядок работы с общим хранилищем VCS.**

**Ответ:** Порядок работы с удалённым репозиторием: `git pull` (получить обновления) → внести изменения → `git add` → `git commit` → `git push` (отправить изменения).

**6. Каковы основные задачи, решаемые инструментальным средством git?**

**Ответ:** Основные задачи: отслеживание изменений, работа с ветками, поддержка совместной разработки, управление версиями, разрешение конфликтов и обеспечение целостности данных.

**7. Назовите и дайте краткую характеристику командам git.**

**Ответ:**
- `git init` — инициализация репозитория.
- `git add` — добавление файлов в индекс.
- `git commit` — фиксация изменений в репозитории.
- `git push` — отправка локальных изменений в удалённый репозиторий.
- `git pull` — получение изменений из удалённого репозитория.
- `git status` — просмотр состояния рабочей директории.
- `git diff` — просмотр различий между версиями файлов.

**8. Приведите примеры использования при работе с локальным и удалённым репозиториями.**

**Ответ:**
- Локальный: `git init`, `git add .,` `git commit -m "..."`.
- Удалённый: `git clone`, `git pull`, `git push`.

**9. Что такое и зачем могут быть нужны ветви (branches)?**

**Ответ:** Ветви (branches) — это независимые линии разработки. Они нужны для параллельной работы над разными функциями, изоляции экспериментальных изменений и командной разработки без риска сломать основную версию.

**10. Как и зачем можно игнорировать некоторые файлы при commit?**

**Ответ:** Для игнорирования файлов создаётся файл `.gitignore`, в котором перечисляются шаблоны имён файлов (например, `*.log`, `build/`). Это делается для того, чтобы временные и служебные файлы не попадали в репозиторий, сохраняя его чистоту и уменьшая размер.
